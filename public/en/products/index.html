E-OS Notesin the image

A notes application for the Crimson desktop, written in Rust with Slint on the shared eos-ui backend.

It stores notes in SQLite in write-ahead-log mode. It is a first-party E-OS component and is pinned by revision in its build recipe.

  • No host window backend yet: it type-checks on macOS and Linux but does not open a window there.
  • No automated tests in the repository yet, and therefore no coverage floor.

E-OS Controlin the image

The control centre: system overview, processes, security, storage, power, sound and live network state.

It absorbed the standalone system monitor and the file-integrity monitor. The Security tab carries the blake3 baseline and the permission audit that used to live in a separate application.

  • No host window backend yet: it type-checks on macOS and Linux but does not open a window there.
  • No automated tests in the repository yet, and therefore no coverage floor.

E-OS Guardin the image

A file-integrity and permission monitor for the Crimson desktop, shipped as an application again since the owner's decision of 2026-09-03.

It keeps a blake3 baseline of the files it watches and reports permission changes. The same engine also runs inside the Security tab of the control centre, from a second copy of the code rather than one shared library — recorded as debt on the roadmap, not hidden.

  • The integrity engine exists twice — in this application and inside the control centre. Merging them into one library is roadmap row PR-004.
  • No signature scanning and no on-access hook. The word "antivirus" is not used for it until such an engine exists (roadmap rows PR-003 and PR-004b).

Deliberately absent

Two of these are choices with reasons and two are gaps the roadmap tracks. The project's own README blurred that distinction once and had to correct it; the distinction is kept here.

  • No antivirus. The word is not used until an on-access engine exists. The security product is E-OS Guard, which does integrity and permission monitoring.
  • No mandatory access control of the SELinux or AppArmor kind. The access-control model is the per-user kernel-scheme allowlist.
  • No backup tool. That is a gap, and the roadmap tracks it as such.
  • No VPN and no Tor. Also gaps: both are new subsystems, not a switch waiting to be flipped.
