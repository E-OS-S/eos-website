Support

A FAQ, a ticket that becomes a GitLab issue, and an AI assistant that is designed and not built.

Security bugs do not go here

Do not open a public ticket for a vulnerability. There are two private channels and both are monitored.

How to report a security problem

Tickets

There is no backend. This site is static files on GitLab Pages, so a form on this page cannot store anything and cannot send anything.

A ticket is therefore an issue in a GitLab project. The form below composes a prefilled "new issue" link inside your browser. Nothing leaves this page until you follow that link, and GitLab is where you review the text and submit it. You need a GitLab account to do so.

Ticket project: e-os/eos-support

Nothing here is transmitted. The button below opens GitLab with the fields already filled in.

Open the prefilled ticket on GitLab

Without JavaScript

These links work with scripting disabled. They carry the issue template only; you type the rest on GitLab.

  • Bug — Something behaves differently from what is documented.
  • Question — You could not find the answer in the documentation.
  • Hardware report — It booted, or it did not, on a specific machine.
  • Documentation — Something on this site or in the documents is wrong or missing.

What this arrangement cannot do

  • Tickets are public. Anything you paste into one is public from the moment it is submitted.
  • You need a GitLab account. There is no anonymous ticket.
  • There is no ticket number until GitLab creates one, and this site sends no email.
  • A very long description does not survive a URL. The composer tells you when the link gets too long; paste the rest into the issue after it opens.
  • Nothing on this page is stored, so a half-written ticket is lost if you close the tab.

AI assistant

Designed, not built

There is no chat on this page and no endpoint behind it. Nothing you type anywhere on this site reaches a model.

The decision, taken on 2026-09-03, is that if E-OS ever has a support assistant then it runs its own model on its own machine. Calling somebody else's hosted service to answer questions about an operating system built around a verifiable trust chain would contradict the premise.

That has a cost, and the cost is why this is a design rather than a feature: E-OS has no GPU driver stack, no linear-algebra library in the image and no server edition that has ever been built. The design document says what a CPU-only Rust host can realistically run and what it cannot.

Design document: docs/ai-chat-design.md

What the design covers

  • A model class that fits a CPU-only host: a one-to-four-billion-parameter instruction-tuned model, quantised, answering from retrieved documentation rather than from memory.
  • Retrieval over the documentation, the changelog and the roadmap, with every answer citing the file it came from.
  • Guardrails: no shell, no filesystem, no ticket creation, and a refusal path for when retrieval finds nothing.
  • Phases with sizes, so that the first phase is useful before the server edition exists.

What it will not be

  • It will not be a wrapper around somebody else's hosted model.
  • It will not answer security questions or triage vulnerabilities.
  • It will not act on your system or open tickets on your behalf.
  • It will not exist at all until the E-OS server edition does.

Frequently asked

Can I run E-OS today?
You can build it and run it in QEMU. Nothing has been booted on physical hardware yet, and the downloads page publishes no images.
Is it Linux?
No. It is a downstream distribution of Redox OS, whose microkernel is written in Rust. Linux binaries do not run on it.
Which architectures?
x86_64 and aarch64. Both reached a userspace login prompt in QEMU on 2026-09-01.
Can I install packages?
On aarch64 the signed package index is live. On x86_64 the image has no active package source, which is tracked as an open defect rather than hidden.
Is there commercial support?
No. It is a single-maintainer project with no legal entity behind it.
Why is the changelog partly in Polish?
Because it was written in Polish, and rewriting a record after the fact would make it less trustworthy rather than more. The page furniture is translated; the record is not.
How do I report that it does not boot on my machine?
Open a hardware report with the machine, the firmware, the architecture and the last line you saw. A photograph of the screen is more useful than a description of it.
Where do the roadmap identifiers this site keeps quoting come from?
From ROADMAP.md in the orchestration repository. Every identifier there carries a size estimate and, where the status says done, the evidence for it.

Channels

There are three, and none of them is a chat room.

  • Tickets — issues in the support project
  • Defects in the orchestration repository
  • Security — GitHub Security Advisories, private

The response targets are the ones in the security policy: 72 hours to acknowledge, seven days to an initial assessment. They are targets from one maintainer, not a contract.
