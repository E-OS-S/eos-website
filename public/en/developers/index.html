Building

The build runs in a container. On the reference host — Apple Silicon macOS with podman — the project directory sits on exFAT, which podman will not mount, so the wrapper builds inside a volume instead. These are the commands that were run, not a summary of them.

bash scripts/eos-build.sh x86_64
bash scripts/ci-boot-smoke.sh ~/eos-artifacts/eos-x86_64-harddrive.img 300 --arch x86_64
bash scripts/verify.sh

Running make directly from the project directory does not work on that host, and make will report that there is nothing to be done while assembling an image from stale artefacts. The wrapper exists for exactly that reason.

Gates

What can go red, and where.

Gates in the orchestration repository
GateWhat it does
scripts/verify.shSixteen stages. Exit 1 means a defect was found; exit 2 means the gate could not run. A missing scanner is exit 2, never a pass.
scripts/ci-integrity.shEighteen invariant checks, plus a probe that checks its own instruments before the first check runs.
scripts/ci-boot-smoke.shBoots the built image in QEMU and waits for a userspace login prompt. PASS on both architectures, measured 2026-09-01.
gitleaks, osv-scanner, cargo-denySecret scanning over the full history, and advisory scanning on both manifests.
coveragecargo llvm-cov with a floor of 38% of lines on the signing tool; 41.06% measured on 2026-09-01. The floor catches regression, it does not certify 38% as a good number.
shellcheckErrors block, warnings are advisory. Zero errors across the shell scripts.

GitLab shared runners are quota-limited and run out intermittently. GitHub Actions has never produced a run for this repository. The self-hosted eos-heavy runner spends no shared minutes and is what the heavy jobs use — including this website's pages job. A local run of verify.sh is the only gate known in advance to execute.

Contributing

The short version of the contract:

  • No commits on main. Branch, then a merge request.
  • No force-push, ever, including on your own branch.
  • One logical change per merge request.
  • Every change has a test, or a written reason why a test is impossible, agreed before the change lands.
  • Never hand-edit a generated file — the lockfiles, the SBOMs, the third-party licence list. Regenerate them.
  • No secrets in the repository or in a log. Generating a signing key is a human action and is deliberately not automated.

This website

The site is a separate repository with static output and no backend. Its own gates run before the build:

npm ci
npm run check:i18n
npm run check:changelog
npm run check:contrast
npm run build

check-i18n fails when a key is missing from a catalogue or when a component carries a bare string in a text position. check-changelog fails when the parser regresses or when the vendored changelog drifts from the orchestration repository. check-contrast measures every colour pair the accessibility statement claims. All three exit 1 for a finding and 2 when they could not run at all.
